**Konteks.** Menetapkan alur: rencana → mockup → persetujuan → implementasi →
tes → verifikasi → commit → learnings.

**Temuan saat memeriksa keadaan repo** (bukan asumsi):

| Temuan | Bukti |
|---|---|
| Mockup sudah ada, tanpa aturan | `mockup/index.html` — mockup v2, 380px, token sama dengan `public/style.css` |
| Tidak ada tes UI sama sekali | tidak ada `playwright`/`puppeteer`/`jsdom` di `package.json`; `npm test` = `node --test tests/*.test.ts` |

| Belum ada ID keputusan | `AGENTS.md` §4 berisi ~10 keputusan sebagai prosa tanpa nomor |

**Keputusan yang lahir:** `DEC-0011` (alur enam langkah), `DEC-0012` (paritas
token mockup), `DEC-0013` (tes UI di workflow terpisah).

**Yang mudah salah diulang:**

1. **Memaksa mockup pada perubahan pipeline.** Sebagian besar pekerjaan di repo
   ini bukan UI. Gerbang harus berbeda per kelas, atau orang akan membuat mockup
   palsu lalu meninggalkan alurnya.
2. **Menulis langkah terakhir sebagai “push”.** Situs belum hidup sampai Pages
   deploy. Langkah terakhir adalah *verifikasi* (`latest_by_scope` cocok, URL
   edisi baru merespons).
3. **Tidak punya jalur darurat.** Insiden 05:45 WIB tidak menunggu persetujuan
   mockup. Tanpa jalur darurat, alur dilanggar pada insiden pertama.
4. **Agen menyetujui rencananya sendiri.** Persetujuan hanya milik manusia;
   agen mengusulkan dan menjalankan.

**Belum selesai.** Harness tes UI masih `plan-draft`
(`docs/plans/001-ui-test-harness.md`). Sampai ia ada, langkah “tes termasuk UI”
belum punya alat.

## 2026-11-11 — Disetujui dan dipecah: 001 versi 2

**Keputusan manusia.** 001 disetujui dengan revisi: asersi yang tidak butuh
browser dipindah ke `tests/` (`DEC-0014`), `serve.ts` boleh berubah (`DEC-0015`).

**Temuan yang mengubah rencana** — ketiganya baru terlihat karena membaca file,
bukan karena membaca rencana:

| Temuan | Bukti |
|---|---|
| Tiga dari tujuh asersi tidak butuh browser | UI-01/02 cukup membaca `public/index.html`; SRV-01 cukup `fetch`. Kalau ditaruh di `tests-ui/`, regresi path baru tertangkap **setelah push** |
| `npm run serve` melayani di akar, produksi di `/edisi-pagi/` | `scripts/serve.ts` — `root = public`, tanpa prefix. Inilah sebab bug path lolos ke produksi |
| `scripts/push.ts` mengunci `url: "./"` tanpa tes | dua tempat (baris 57, 71); `AGENTS.md` §5 mencatat bug ini pernah terjadi |
| `publish.ts` menulis ulang `public/index.html` di tempat | `publish.ts` mengganti `app.js`/`style.css` dengan `?v=<sha1>`; berkas di repo adalah hasil publish |

**Bukti implementasi commit 1.** `npm test` 195 lulus (190 + 5),
`npm run typecheck` bersih. Tiga uji negatif dijalankan sungguhan — merusak
perilaku membuat tesnya gagal:

- `src="app.js?v=…"` → `src="/app.js?v=…"` ⇒ UI-01, UI-02 gagal.
- `url: "./"` → `url: "/"` di `push.ts` ⇒ PUSH-01 gagal.

**Pelajaran.**

1. **Anggaran status `plan-draft` murah, dan itu gunanya.** Membaca tiga file
   sebelum implementasi mengubah bentuk rencana secara material. Kalau langsung
   ditulis, tiga asersi akan tinggal di tempat yang salah selamanya.
2. **Uji negatif wajib dijalankan, bukan diasumsikan.** Menulis “uji ini akan
   gagal kalau X rusak” tidak membuktikan apa pun. Merusak perilakunya selama
   satu menit membuktikannya.
3. **Asersi “server menolak di luar prefix” adalah penjaga meta.** Tanpa 404
   itu, suite bisa lulus sambil menguji akar domain — dan bug yang ingin
   dicegah tidak pernah tereproduksi.
4. Port acak (`PORT=0`) menghapus seluruh kelas flakiness “port sudah dipakai”
   tanpa biaya.
