Catatan **apa yang terjadi**: gejala, bukti, angka, sebab. Aturannya:

  berharga.

- Arsip sesi 10–11 November 2026 yang lebih panjang tetap di
  `SESSION-LEARNINGS.md`; file ini mulai dari sesi berikutnya.

## 2026-11-11 — Alur kerja berbasis rencana

**Konteks.** Menetapkan alur: rencana → mockup → persetujuan → implementasi →
tes → verifikasi → commit → learnings.

**Temuan saat memeriksa keadaan repo** (bukan asumsi):

| Temuan | Bukti |
|---|---|
| Mockup sudah ada, tanpa aturan | `mockup/index.html` — mockup v2, 380px, token sama dengan `public/style.css` |
| Tidak ada tes UI sama sekali | tidak ada `playwright`/`puppeteer`/`jsdom` di `package.json`; `npm test` = `node --test tests/*.test.ts` |
| Dokumentasi membludak | 10 file, 4.825 baris (`REQUIREMENTS.md` 627, `NEWSROOM.md` 862, `SCHEMA.md` 857) |
| Belum ada ID keputusan | `AGENTS.md` §4 berisi ~10 keputusan sebagai prosa tanpa nomor |
| `SESSION-LEARNINGS.md` berskala satu sesi | judul “10–11 November 2026”, 280 baris |

**Keputusan yang lahir:** `DEC-0011` (alur enam langkah), `DEC-0012` (paritas
token mockup), `DEC-0013` (tes UI di workflow terpisah).

**Yang mudah salah diulang:**

1. **Memaksa mockup pada perubahan pipeline.** Sebagian besar pekerjaan di repo
   ini bukan UI. Gerbang harus berbeda per kelas, atau orang akan membuat mockup
   palsu lalu meninggalkan alurnya.
2. **Menulis langkah terakhir sebagai “push”.** Situs belum hidup sampai Pages
   deploy. Langkah terakhir adalah *verifikasi* (`latest_by_scope` cocok, URL
   edisi baru merespons).
3. **Tidak punya jalur darurat.** Insiden 05:45 WIB tidak menunggu persetujuan
   mockup. Tanpa jalur darurat, alur dilanggar pada insiden pertama.
4. **Agen menyetujui rencananya sendiri.** Persetujuan hanya milik manusia;
   agen mengusulkan dan menjalankan.

**Belum selesai.** Harness tes UI masih `plan-draft`
(`docs/plans/001-ui-test-harness.md`). Sampai ia ada, langkah “tes termasuk UI”
belum punya alat.

## 2026-11-11 — Disetujui dan dipecah: 001 versi 2

**Keputusan manusia.** 001 disetujui dengan revisi: asersi yang tidak butuh
browser dipindah ke `tests/` (`DEC-0014`), `serve.ts` boleh berubah (`DEC-0015`).

**Temuan yang mengubah rencana** — ketiganya baru terlihat karena membaca file,
bukan karena membaca rencana:

| Temuan | Bukti |
|---|---|
| Tiga dari tujuh asersi tidak butuh browser | UI-01/02 cukup membaca `public/index.html`; SRV-01 cukup `fetch`. Kalau ditaruh di `tests-ui/`, regresi path baru tertangkap **setelah push** |
| `npm run serve` melayani di akar, produksi di `/edisi-pagi/` | `scripts/serve.ts` — `root = public`, tanpa prefix. Inilah sebab bug path lolos ke produksi |
| `scripts/push.ts` mengunci `url: "./"` tanpa tes | dua tempat (baris 57, 71); `AGENTS.md` §5 mencatat bug ini pernah terjadi |
| `publish.ts` menulis ulang `public/index.html` di tempat | `publish.ts` mengganti `app.js`/`style.css` dengan `?v=<sha1>`; berkas di repo adalah hasil publish |

**Bukti implementasi commit 1.** `npm test` 195 lulus (190 + 5),
`npm run typecheck` bersih. Tiga uji negatif dijalankan sungguhan — merusak
perilaku membuat tesnya gagal:

- `src="app.js?v=…"` → `src="/app.js?v=…"` ⇒ UI-01, UI-02 gagal.
- `url: "./"` → `url: "/"` di `push.ts` ⇒ PUSH-01 gagal.

**Pelajaran.**

1. **Anggaran status `plan-draft` murah, dan itu gunanya.** Membaca tiga file
   sebelum implementasi mengubah bentuk rencana secara material. Kalau langsung
   ditulis, tiga asersi akan tinggal di tempat yang salah selamanya.
2. **Uji negatif wajib dijalankan, bukan diasumsikan.** Menulis “uji ini akan
   gagal kalau X rusak” tidak membuktikan apa pun. Merusak perilakunya selama
   satu menit membuktikannya.
3. **Asersi “server menolak di luar prefix” adalah penjaga meta.** Tanpa 404
   itu, suite bisa lulus sambil menguji akar domain — dan bug yang ingin
   dicegah tidak pernah tereproduksi.
4. Port acak (`PORT=0`) menghapus seluruh kelas flakiness “port sudah dipakai”
   tanpa biaya.

## 2026-11-11 — Commit 2: lapisan browser

**Hasil.** 4 uji Playwright lulus atas fixture sungguhan di `/edisi-pagi/`,
dua kali berturut-turut (4,0 detik lalu 978 ms). `ROOT` ditambahkan ke
`serve.ts` (§Revisi v3) supaya suite dan `npm run serve` memakai server yang
sama.

**Uji negatif.** Registrasi SW diubah menjadi `sw-tidak-ada.js` ⇒ UI-06 gagal
(`waitForFunction` timeout 30 detik), tiga uji lain lulus. Dipulihkan.

**Pelajaran.**

1. **Uji offline yang lulus dalam 131 ms patut dicurigai, bukan disyukuri.**
   Itu sebabnya uji negatif dijalankan. Tanpa itu, UI-06 bisa saja lulus karena
   halaman masih di memori browser, bukan karena service worker.
2. **`fixtures/ui/` lebih baik daripada memakai edisi terbit.** Edisi terbit
   berubah setiap pagi; tes yang bergantung padanya akan merah tanpa ada kode
   yang berubah. Fixture mengganti kartu `gap` menjadi `misread` agar meta tetap
   2 (batas skema) sekaligus memenuhi kebutuhan UI-07.
3. **Pilih selektor dari kode, bukan dari tebakan.** `button.card`, `.it[data-nav]`,
   `.missing .lbl`, `#atur .plbl` dibaca dari `app.js`/`index.html`. Selektor
   tebakan adalah sumber flakiness yang paling mahal diperbaiki.
4. **Satu worker, berurutan.** Service worker dan cache bersifat global per
   origin; paralelisme di sini membeli kecepatan dengan flakiness.

## 2026-11-11 — Biaya sebagai kebijakan: DeepSeek jadi opt-in

**Permintaan pemilik proyek.** “Disable deepseek direct api, use opencode
exclusively; saldo DeepSeek rendah.”

**Yang ternyata terjadi.** DeepSeek bukan sekadar cadangan yang bisa dimatikan
di CI. `resolveLlm` memakai `!forced` pada syarat DeepSeek, jadi kunci itu aktif
otomatis **tanpa** `LLM_PROVIDER`. Menghapus secret dari `daily.yml` saja tidak
cukup: agen atau skrip lain yang menjalankan pipeline dengan `.env.local` akan
tetap mengeluarkan biaya.

**Keputusan.** Invarian dikunci di kode dan di tes (`DEC-0016`), bukan di
konfigurasi: penyedia berbayar hanya aktif bila diminta eksplisit.

**Bukti.** 4 uji baru; uji negatif dijalankan dengan mengembalikan `resolve.ts`
ke versi `HEAD` → uji “tanpa LLM_PROVIDER, DeepSeek tidak dipakai” **gagal**
(kode lama memilih `deepseek`). Dipulihkan → lulus.

**Pelajaran.**

1. **“Cadangan otomatis” pada penyedia berbayar = keputusan pengeluaran yang
   diambil oleh kegagalan jaringan.** Tidak ada manusia yang memilih; saldo
   berkurang saat OpenCode kebetulan down.
2. **Matikan di kode, bukan hanya di secret.** Secret bisa dipulihkan tanpa
   sengaja; default di kode adalah satu-satunya tempat yang berlaku untuk semua
   pemanggil.
3. **Ongkos turun, kualitas juga.** Tanpa OpenCode, writer menjadi
   deterministik. Itu harus terlihat di log, bukan terasa belakangan:
   `opencode tidak tersedia — memakai penulis deterministik (DeepSeek nonaktif, DEC-0016)`.
4. **`OPENCODE_MODEL=opencode-go/deepseek-v4.1-flash` tetap memakai model
   DeepSeek** — lewat langganan OpenCode. Yang dinonaktifkan adalah kunci API
   langsung, bukan modelnya. Mudah keliru saat membaca log.

## 2026-11-11 — Model dipatok, dan tiga dokumen yang ternyata berbohong

**Permintaan.** “In opencode, always use deepseek flash model.”

**Yang sudah benar.** `OPENCODE_MODEL=opencode-go/deepseek-v4.1-flash` sudah ada
di kedua workflow dan sudah menjadi default di `resolve.ts`. Jadi tidak ada bug
model yang perlu diperbaiki.

**Yang ternyata salah: dokumentasinya.**

| Temuan | Bukti |
|---|---|
| Konfigurasi per-kapabilitas tidak pernah dipakai | `src/config/llm.ts`: `loadLlmConfig`, `validateLlmConfig`, `DEFAULT_CONFIG` tanpa pemanggil; hanya tipe yang diimpor |
| `INFRA.md` §11.2 masih menjelaskan DeepSeek sebagai cadangan | bertentangan dengan `DEC-0016` yang baru ditulis |
| `config/llm.example.yaml` menyarankan `deepseek-v4-pro` untuk `verify` | menyalin contoh itu berarti memakai model lebih mahal |

**Pelajaran.**

1. **Kebijakan yang benar tetap perlu dikunci tes.** “Sudah flash di CI” adalah
   keadaan, bukan jaminan. `tests/llm-model.test.ts` membandingkan default kode
   dengan kedua workflow, jadi pergeseran model muncul sebagai tes merah.
2. **Artifact mati tetap dibaca orang.** `config/llm.example.yaml` tidak dipakai
   kode, tetapi ia satu-satunya contoh yang akan disalin sesi berikutnya. Beri
   header “belum terpasang”, jangan biarkan ia menyarankan konfigurasi yang
   bertentangan dengan keputusan terbaru.
3. **Mengubah keputusan berarti menyisir dokumen lama.** `DEC-0016` dibuat
   beberapa menit sebelum temuan ini, dan `INFRA.md` sudah bertentangan
   dengannya. Tanpa penyisiran, dokumentasi menua lebih cepat daripada kode.
